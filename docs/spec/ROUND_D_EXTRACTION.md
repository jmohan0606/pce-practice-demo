## 2 · Global transformation rules

Applied in `build_real_data.py`, not in SQL. Getting any of these wrong corrupts everything silently.

**Account key.** `normalize_account_key()` — the one shared function in `app/shared/ids.py`
(`ltrim(trim(x),'0')`). Every account column: `account_no`, `account_number`, `wm_acct_src_nb`. Keep
the raw value in the matching `*_raw` column. A key normalising to empty stays empty — never invent.

**Credited revenue.**
```
reason_cd        = COALESCE(NULLIF(trim(reason_cd),''), '__NONE__')
credited_amt     = post_split_credited_amt when reason_cd == '__NONE__' else 0
non_credited_amt = post_split_credited_amt when reason_cd != '__NONE__' else 0
is_credited      = reason_cd == '__NONE__'
```
Reason-coded rows are **still loaded** — excluded from credited totals, visible to the agent.

**Never join trades to `fpic_team_agreement_tb`.** `post_split_credited_amt` already carries the team
share (verified: `split_pct == prm_share_pct`). Joining also fans out one row per secondary member,
multiplying revenue. Team agreements are reference data only.

**Month** = `to_char(trade_dt,'YYYYMM')`. **Never `proc_dt`** — it runs after month end and
mis-assigns rows across boundaries.

**No PII** ever extracted: `tax_id`, `tax_id_type`, `mail_addr_line_1..6`, `mail_addr_zip_cd`,
`account_name`, `cust_full_nm`, `prty_shrt_nm`.

**Formatting.** Booleans lowercase `true`/`false`. Timestamps `YYYY-MM-DD HH:MM:SS`, dates
`YYYY-MM-DD`. Empty string for null strings, `0` for null numerics. CSV `QUOTE_MINIMAL`, UTF-8,
**LF endings** (`open(..., newline='')`).

**Scope:** `trade_dt >= '2026-04-01' AND trade_dt < '2026-07-01'`, 20 cohort advisors.

## 5 · `build_real_data.py`

Mirrors V2's script. **`RAW_CONTRACT`** — a dict of the 10 raw filenames with their exact expected
columns. A missing file or column raises **`ColumnMismatchError`** naming both. Never a silent
partial build.

Then: apply §2 transformations, import the product model from `app/revenue/products.py`, compute the
derived vertices from §3, generate dummy opportunities, derive all 29 edge files, write
`data/real/{vertices,edges}/` and a `manifest.json` **with the same structure the mock generator
produces** — same keys, same column maps, so the ingestion pipeline consumes it unchanged.

### Validation printed at the end — stop on any failure

```
 1. row count per file (46 files)
 2. primary key uniqueness per vertex file — 0 duplicates
 3. acct_key values with leading zeros — must be 0
 4. reason_cd empty strings — must be 0
 5. rows where reason_cd != '__NONE__' AND credited_amt != 0 — must be 0
 6. product_ids not in the mapping — list with row counts (kept as unmapped, never dropped)
 7. monthly_revenue totals vs an independent re-sum of the transaction file — must match
 8. dropped edges per file
 9. prior_credited_amt populated for 202605/202606, zero for 202604
10. scenario coverage: fee reduction >10% and how many have a recorded grid_reduction;
    transfers in/out; accounts opened in scope; accounts zeroed; team agreements; advisors with flows
11. per-month credited_amt and txn_count for 202604 / 202605 / 202606
12. trading days per month
```

**Sanity anchor for line 11:** a published reference figure implies roughly $363M/month across
10,899 advisors — about $33k per advisor per month. A 20-advisor cohort selected for high revenue
should land in the high hundreds of thousands to low millions per month. An order of magnitude out
means `proc_dt` was used instead of `trade_dt`, or the team-agreement join fanned out.

## 6 · Load and verify

```bash
DATA_DIR=data/real uv run python scripts/load_real_data.py
DATA_DIR=data/real uv run python scripts/verify_real_data.py
```

Ingestion is the existing manifest-driven upsert pipeline — batched per `entity_registry`,
checkpointed, loaded counts verified against the manifest, failing loudly on mismatch. **No GSQL
loading jobs run.** The `docs/tigergraph/loading/*.gsql` files are documentation only.

Schema DDL **is** still required as a one-time install — upserts fail if the vertex types do not
exist:

```
01_vertices.gsql -> 02_edges.gsql -> 03_create_graph.gsql
```

GSQL V1 constraints, all three of which cost a round in V2: parameter order is `TYPE name`;
traversal targets must be vertex types with edge aliases; multi-hop patterns split into single-hop
SELECTs.

**Keep the mock dataset.** `DATA_DIR` switches between them; mock is the fallback if the real
extract proves unusable mid-demo.
