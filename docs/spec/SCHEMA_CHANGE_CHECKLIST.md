# Schema Change Checklist

**Anything added to the graph must be added in ALL FIVE places in the same
commit, or the client load will fail.** This list exists because a missed spot
is invisible locally (the tiered client falls back) and fatal on the client's
live TigerGraph.

For every new vertex, edge, or attribute:

1. **GSQL DDL** — `docs/tigergraph/schema/`-equivalent files:
   - `docs/tigergraph/01_vertices.gsql` (vertex + attributes)
   - `docs/tigergraph/02_edges.gsql` (edges, each with its REVERSE_EDGE)
   - `docs/tigergraph/03_create_graph.gsql` (add to the graph's type list)
   - `docs/tigergraph/90_drop_all.gsql` (drop in EXACT reverse create order —
     verify_round_a check 2c pins this)
   - source-loaded vertices also need `docs/tigergraph/loading/load_<name>.gsql`
     (HEADER="true", SEPARATOR=",", QUOTE="double" — check 2d pins the QUOTE)
     and, for edges, entries in `loading/load_edges.gsql`
2. **`docs/tigergraph/schema_catalog.json`** — vertex attributes + edge entries.
   The rule compiler, graph mirror, and get_schema tool all resolve fields here.
3. **`data/manifest.json`** — file entry with its column map. The manifest is
   GENERATED by `scripts/generate_mock_data.py`; add the entity there (see 4)
   and regenerate rather than hand-editing the manifest.
4. **`scripts/generate_mock_data.py`** — builder function + `VERTEX_COLUMNS`,
   `ID_COLUMNS`, and `EDGES` entries, then run it to regenerate `data/` and the
   manifest.
5. **`docs/spec/SCHEMA_SPEC.md`** — the vertex/edge section AND the vertex/edge
   count line at the end of §3.

App-written (runtime) vertices skip 3 and 4 (no CSV load) but need their mirror
entry in the owning store (`app/insights/store.py` / `app/rules/store.py` /
`app/knowledge/graph_writer.py`) instead — the runtime upsert is their "loading
job".

After the change: run `python3 scripts/generate_mock_data.py`, then
`verify_round_a.py` / `verify_round_b.py` / `verify_round_c.py` — check 2c
(drop order), 2d (QUOTE) and 2e (catalog coverage) catch most misses.
